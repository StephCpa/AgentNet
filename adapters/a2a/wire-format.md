# A2A 1.0 wire registry

Checked 2026-10-27. Freeze upstream **v1.0.1**, commit
[`3303592588e388e62e0f69f701af531d2f4e3991`](https://github.com/a2aproject/A2A/tree/3303592588e388e62e0f69f701af531d2f4e3991).
The normative [proto](https://github.com/a2aproject/A2A/blob/3303592588e388e62e0f69f701af531d2f4e3991/specification/a2a.proto)
is vendored in `test/prt/upstream/a2a.proto` with the upstream Apache-2.0 license.
JSON-RPC names come from the pinned [specification §9.4](https://github.com/a2aproject/A2A/blob/3303592588e388e62e0f69f701af531d2f4e3991/docs/specification.md#94-core-methods).

| AgentNet operation | JSON-RPC method | gRPC method in lf.a2a.v1.A2AService | HTTP+JSON method/path |
|---|---|---|---|
| SubmitCommand | SendMessage | SendMessage | POST /message:send |
| Streaming submit | SendStreamingMessage | SendStreamingMessage | POST /message:stream |
| GetTask | GetTask | GetTask | GET /tasks/{id} |
| Subscribe | SubscribeToTask | SubscribeToTask | GET /tasks/{id}:subscribe |
| Cancel | CancelTask | CancelTask | POST /tasks/{id}:cancel |

Tenant-prefixed paths are also defined in the proto; JSON-RPC uses the endpoint
advertised by the Agent Card, rather than these HTTP+JSON resource paths.

The pinned specification's summary table §8 lists **POST** for SubscribeToTask,
but the proto's `google.api.http` annotation says **GET**. This registry follows
the proto and records the discrepancy. An independent peer test must settle
compatibility before enabling that binding; this is not an interoperability pass.

`test/prt/upstream/get-task.json` is the request copied from upstream §9.4.3;
it is an external fixture, not generated by an AgentNet adapter. `test/prt/check_wire.py`
checks the registry against the pinned proto and this fixture. No adapter exists yet.

Extension work remains: the A2A Agent Card uses `capabilities.extensions[].uri`;
`protocols.anet_extensions` is not a core A2A field. Additional SendMessage data
belongs in `metadata`; `GetTaskRequest` has only tenant/id/history_length and no
`by_command`. `x-anet-ra/0.1` needs a negotiated extension URI and an explicit
command lookup operation before it can be an executable protocol specification.
