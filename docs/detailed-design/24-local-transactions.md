# 24 · 本地业务与账本原子提交

状态：2026-10-27，M1 增量；完整 M0–M4 退出条件不变。

## 事务边界

`ExecuteLocalEffect` 在原 T2 守卫后执行受控本地处理器，在同一个 PostgreSQL 事务中提交业务变更、effect 终态、持久结果、预算结算、task_version、事件和审计。新的 local-tx effect 不能经普通 `AdmitEffect` 接纳；不创建异步执行作业或派发 outbox。三类外部目标继续使用 18 的执行/对账路径。

参数先执行 RFC 8785 规范化，实际正文摘要必须等于提案与签名决定绑定的摘要。配置决定 action/resource/handler，正文不能选择处理器、资源命名空间或 SQL。首个处理器为 `record.put/v1`，按域、资源、键执行版本比较后写入；版本不符产生持久 REJECTED，业务行不变。成功与版本拒绝均由服务计量 calls=1，其余三维为 0。

锁序延续 tasks → grants/consent → budget_accounts → reservations → effects，最后取得业务键锁。不存在的键也用事务 advisory lock 串行化。业务执行及最终落库可能等待，因此提交前再次验证主体/凭证、任务期限、决定期限、租约与 grant/consent 期限。已持有的控制行锁不会在业务阶段反向获取。

计量必须同时不超过预留量和提案 upper_bound。超限、无效计量、处理器失败或审计失败将整个事务回滚，包括业务写入；此处不复用外部操作“事实已发生，保留超额并冻结”的路径。处理器是经评审的受信代码；窄 DB 接口不是隔离恶意 SQL 或网络访问的沙箱。

## 重放与恢复

迁移 011 新建 `local_records` 与 `local_effect_results`。业务结果独立保存，之后更新业务行不会改变旧 effect 的结果。精确重放在现有 task 所有权和实时身份校验后返回原结果，不要求重取已过期的执行许可；冲突提案仍落原有 conflict_attempts，不改原 effect。

| 中断位置 | 可见事实 | 重试 |
|---|---|---|
| 业务写入后、事务提交前 | 整个事务回滚，预留仍未绑定 | 原提案重新经过守卫执行 |
| 提交后、调用方拿到结果前 | 业务、结算和结果已同时落库 | 原 effect 返回 EXISTING 与原结果 |
| 两个任务竞争同一初始版本 | 一个 COMMITTED，一个 REJECTED | 两个结果均可独立重放 |

`local-effect:` 为本地结果标识，不等同于 ART 产物或 PRODUCED/VERIFIED 回执。配置、参数、计量与回滚操作见 [adapters/local](../../adapters/local/README.md)。跨域原子提交、多库事务、任意外部副作用不在此能力类内。

## 验证

数据库测试覆盖实际正文绑定、精确重放、冲突、异步入口拒绝、预算上限、无效计量、业务参数校验、审计失败、并发 CAS、更新后的旧结果重放、取消/提交竞态、锁等待期间期限变化或主体撤销及真实子进程提交前/后终止。mTLS 测试覆盖 ICS 决定到 local-tx 的网络入口，独立 `anetd` 读取注册处理器配置并完成业务写入及重启后的原结果恢复。最终通过 **34 项 runner 检查、111 项数据库集成测试、7 项单测**；`go vet ./...` 与 11 个生成绑定文件漂移检查通过。证据见 [localtx](../../test/evidence/2026-10-27/localtx/)。首轮修正了测试夹具；第二轮既有身份测试遭遇 Windows 临时可执行文件占用清理失败，最终以未变更源码在新隔离库完成全量通过。
