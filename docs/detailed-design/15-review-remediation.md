## 2. 实测结果

持久证据：[`test/evidence/2026-10-27`](../../test/evidence/2026-10-27/)。重跑入口：[`test/tla/README.md`](../../test/tla/README.md)、[`test/schema/README.md`](../../test/schema/README.md)、[`adapters/a2a/wire-format.md`](../../adapters/a2a/wire-format.md)。

| 检查 | 本轮结果 | 能说明什么 |
|---|---|---|
| TaskMachine | 4,080,889 生成 / **383,593 不同状态** / 深度 15，Inv + 6 动作性质通过 | 有界原子模型中的任务、预算、身份和提案代次安全 |
| CmdExpiry | 10 不同状态，通过 | 时效守卫、清理守卫、去重前置共同防止重复创建 |
| BudgetLedger | 8,008 不同状态，通过 | 单子域权利与父账 D 的守恒，不包含重复消息去重 |
| AuthzShrink | 33 不同状态，通过 | 连续授权链收缩，不包含 ICS 决定签名/复用 |
| 变异 | **12/12 指定性质检出**；包括早清理、漏去重两个已知开发期缺陷 | 性质能观察这些错误；不是全部实现缺陷枚举 |
| PostgreSQL 16.15 + pgcrypto | 修正 001：**20 项检查通过**；旧 001+002：**21 项检查通过** | 全量迁移、合法结算、多维绑定、非法复绑、账户约束、T1 写序/分区和账户锁并发探针 |
| 原 SQL 反例 | four-dimensions-one-effect 被 uq_reservation_effect 拒绝 | 确认本轮修复针对真实可复现缺陷 |
| A2A | 官方 v1.0.1 静态契约检查通过 | 来源已固定，适配器和独立对端尚未运行 |

SQL 的 not_after CHECK 只约束时间字段顺序，不能防止任意 DELETE；必须配合 expires_at < 当前时刻的清理规则。时效模型不证明 PostgreSQL 锁等待或时钟回拨安全。数据库探针执行的是 DDL 与明确的事务序列，仓库仍没有 TCS 服务实现。
