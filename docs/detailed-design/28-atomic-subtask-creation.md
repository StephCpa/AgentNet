# 28 · 单域子任务原子创建

状态：2026-10-27，第 28 阶段创建快照。后续本域子树结清与取消传播见 [29](29-subtask-closeout-and-cancellation.md)；完整 M1/M2 尚未退出。

## 接纳与执行身份

`TaskControl.CreateSubtask` 接受受信命令签发者签署的 `anet.subtask/1` 封装，旧的未签名字段必须为空。封装绑定调用身份、父任务/grant、租约、epoch、父任务版本、接收方 Agent/实例/策略、子契约、权限与时间窗、四维预留和 `not_after`。凭证身份仍由 mTLS 得到，封装中的 Caller 必须与其相等。

根授权可由实际用户同意明确批准委托深度和范围；T1 同时要求契约允许委托且不缩小已声明的根深度/范围。子任务的 owner/授权 subject 保持为原用户，actor 改为接收实例。接收方通过自己的凭证取得该子任务租约、申请预留、获取决定和接纳操作；决定的 subject 不能被接收方 principal 替换。原用户可以管理任务，不能冒充子 grant 的 actor 执行业务。

任务 owner、接收 Agent 与直接创建 Agent 可查询/管理该子任务；接收方不能借此访问父任务或其他分支。业务接纳和再次委托仍独立检查 grant actor 与有效租约，管理访问不等于执行权。

## 单事务与账本

迁移 `013_subtasks.sql` 增加接收方策略、委托创建记录和预算分配记录，并使每任务/维度只有一个账户。策略由可信部署管理方预置，绑定域、Agent、实例、版本、完整权限及时效；正文不可原地修改，只能撤销或发布新记录。撤销该策略阻止后续创建，既有子 grant 的撤销走 grant API/祖先撤销。此阶段尚未提供接收方策略管理 UI 或跨域策略交换。

事务先串行化 command_id，锁父任务、完整授权链、根同意、接收方策略、按 ID 排序的父账户和预留。契约检查包含父委托开关、绝对深度、任务类型范围、每父节点的活跃直接子任务上限和子 deadline；权限先拒绝扩大父授权的提案，再与接收方策略求交集。所有等待后复查调用方/接收方、根主体、授权时间窗、命令期限、父任务状态和租约。

每个非零维度要求一笔金额完全相同、未绑定、HELD 的 `subtask` 预留。提交时预留记为 RELEASED/delegated 退出 H，父账户 D 等额增加，子账户 B 等额建立，并持久绑定原预留、父子账户和子任务。零维度不造正金额预留，仍建零额度子账户。账本始终保持 S+H+D≤B；子任务的后续预留使用其实际子账户。

同一事务还创建子契约、任务、grant、命令去重记录、ACCEPTED 回执、父子事件及 outbox，父任务版本递增一次。相同签名命令恢复原事实；内容变化拒绝，超出签名期限即使去重记录已清理也拒绝。回执返回中的 `root_grant_id` 为该次接纳生成的 grant：SubmitCommand 返回根，CreateSubtask 返回子；名字为已有线协议兼容字段。

## 验证

真实 mTLS/PG 用例覆盖跨主体创建、嵌套任务、H→D 与子账户、零维度、重放/冲突、守卫拒绝、事务末段注入失败及账户/策略锁等待。出站测试使用实际创建的跨主体子任务，检查正常发送与原主体撤销后禁止发送。正式冻结运行通过 **39 项 runner 门禁、137 项数据库集成测试、13 项 Go 单测**；四个进程 helper 排除，包含单独 MinIO 门禁。`go vet ./...`、微基准标签 vet 与 11 个生成绑定检查通过。

证据见 [subtasks](../../test/evidence/2026-10-27/subtasks/)。其中保留一次 Windows 临时可执行文件占用导致的清理失败：业务断言未失败，进程已退出，随后原文件 DELETE-access 探针成功；保持源码不变，在新集群重跑全部门禁通过。失败日志、恢复探针与成功结果分别保留，没有把失败运行记为通过。

[微基准复测](../../test/evidence/2026-10-27/subtasks/microbench-report.md) 完成 4,800 次操作、13,200 次 RPC，失败/误拒绝为 0，数据库事实核对通过。该测量覆盖原根控制路径，不测量委托延迟，不据此推断生产容量或相对上一版本的因果性能变化。隔离 PG 集群已停止。
