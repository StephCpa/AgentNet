# 00 · 范围、术语与设计约定

状态：v0.1 草案（未评审） ｜ 上游：总体方案全文

## 1. 范围

本详细设计覆盖总体方案第五章至第十四章确定的系统，即：**运行在现有互联网之上、以信任域为边界联邦组织、以任务契约为协作单位的 Agent 网络系统**。第一版实现一个可运行闭环：

> 三个信任域、两种 Agent 协议（A2A、MCP）、一个工具接口体系，围绕同一项长期任务完成发现、委托、预算分配、执行、证据回传、故障恢复和验收。

### 1.1 非目标（第一版明确不做）

| 非目标 | 原因（总体方案依据） |
|---|---|
| 全局单一中心控制平面 | 联邦架构是主架构（§5.1） |
| 严格实时控制（机器人、音视频） | 需另行设计传输与控制机制（§一） |
| 同时对抗所有域的身份服务/密钥管理/权威库被攻破 | 超出故障模型（§4.1） |
| 结果业务正确性的数学证明 | 网络保证约束与可核查记录，结果正确性靠验证器（§4.3、§11.3） |
| 学习型路由、自动组队、语义压缩、DP 共享的首版强制落地 | 闭环验证后再叠加（§十五前置结论） |
| 消息队列 / 工作流引擎在 MVP 中承担权威状态 | 权威状态单一来源原则（§13.3） |

## 2. 组件命名

全组文档统一使用以下组件缩写。逻辑组件可合并部署（见文档 12），但接口按此边界定义。

| 缩写 | 名称 | 职责（总体方案 §5.2–5.3） |
|---|---|---|
| **GW** | 域网关 Domain Gateway | 唯一出入域流量通道：认证、策略执行、预算执行点、路由、协议适配、审计 |
| **ICS** | 身份与策略服务 Identity & Policy Service | 主体注册、令牌签发/交换（RFC 8693）、授权决策（PDP）、撤销注册 |
| **DIR** | 能力目录服务 Capability Directory | 签名能力描述的注册、查询、联邦同步 |
| **TCS** | 任务控制服务 Task Control Service | 命令接纳、任务状态机、版本/epoch、预算账本、业务操作账本、outbox |
| **ADP** | 执行适配器 Execution Adapter | 面向具体目标（A2A 对端、MCP 服务器、本地工具、业务系统）的幂等执行与对账 |
| **ART** | 产物与证据存储 Artifact & Evidence Store | 内容寻址对象存储、版本化清单、访问控制 |
| **RUN** | Agent 运行时 Agent Runtime（+SDK） | 模型推理、计划提出；**其提议必须经 TCS/ICS/GW 校验后才生效** |
| **OBS** | 观测与审计 Observability & Audit | OTel 遥测、审计事件流水（内容最小化） |

## 3. 术语表

| 术语 | 定义 |
|---|---|
| 信任域 Trust Domain | 拥有独立身份、策略、目录与执行控制的组织边界（企业/实验室/租户） |
| 任务契约 Contract | `goal/input_refs/output_schema/acceptance_policy/...` 的结构化集合（03 §2） |
| 命令 Command | 一次逻辑请求，`command_id` 重传不变；接纳以持久提交为准 |
| 业务操作 Effect | 一次改变外部状态的操作，`effect_id` 重试不变，绑定参数摘要 |
| 尝试 Attempt | 一次实际执行（网络发送/调用），`attempt_id` 每次不同 |
| 接纳 Admission | 权威方持久记录"承担该命令/操作"并返回 `ACCEPTED` 回执的动作 |
| 回执 Receipt | `ACCEPTED` / `PRODUCED` / `VERIFIED` 三级（04 §2） |
| epoch | 任务执行代次；旧 epoch 的操作接纳被拒绝（fencing，04 §5） |
| 预算账本 Budget Ledger | 维护 `S + R ≤ B` 的权威记账（05） |
| 预留 Reservation | 执行前原子锁定的额度，结算或显式确认后才释放 |
| 对账 Reconciliation | 对 `UNKNOWN` 业务操作查询外部系统以确定最终结果的过程 |
| 披露标签 Disclosure Label | 产物/上下文上"允许谁、以何用途、能否再转交"的机器可读限制（09） |
| 幂等能力类 Idempotency Class | 目标系统的恢复能力分级：`local-tx / idempotent-key / queryable / opaque`（04 §4） |
| 补取 Refetch | 接收者发现信息不足时按权限与预算申请追加证据（09 §6） |
| PDP / PEP | 策略决策点 / 策略执行点 |

## 4. 设计约定（全组文档适用）

### 4.1 规范用语

采用 RFC 2119 语义：**必须**（MUST）、**不得**（MUST NOT）、**应**（SHOULD）、**可以**（MAY）。

### 4.2 标识、摘要与时间

| 项 | 约定 |
|---|---|
| ID 格式 | `{kind}_{UUIDv7}`，kind ∈ `dom usr org agt ins con task cmd eff att res grt rct msg evm acc`；例如 `task_0192f0a1b2c3d4e5` |
| 摘要 | `sha256:` + 小写 hex；输入为 **RFC 8785 JCS（JSON Canonicalization Scheme）** 规范化字节流（v0.2 评审 §十：原"UTF-8、键排序、无空白"不足以跨语言一致——`1.0` 在 Python 与 Node 序列化不同） |
| 时间 | RFC 3339，一律 UTC；`deadline` 一律绝对时间戳 |
| JSON Schema | 2020-12 方言 |
| 内部服务间协议 | gRPC（`anet.<svc>.v1`），见各服务文档 |
| SDK 边缘 | HTTPS + JSON；错误码见 4.4 |
| 跨域线协议 | 标准 A2A 1.0 / MCP 2026-07-28 + 协商扩展（08） |
| 内部命令封装 profile | `agent-network/0.1`（总体方案 §6.4 原样沿用） |

**JCS 输入约束（所有进入摘要计算的字段必须满足）**：数字不得使用 Infinity/NaN；浮点须可由 IEEE 754 double 精确往返；金额一律使用规范十进制字符串（无前导零、无多余小数位）；整数绝对值 < 2^53；字符串须为合法 UTF-8（无未配对代理项）；对象无重复键。违反约束的数据在摘要计算前被拒绝（`ANET-CMD-CANON-INVALID`）。

**跨语言测试向量**：[`test/vectors/canonicalization.json`](../../test/vectors/canonicalization.json)；Python（RFC 8785 库或等价实现）、Go（RFC 8785 库）、Node（原生对照）三方 CI 断言同一 digest（M1 门禁）。effect 的 `params_digest` 绑定范围 = 目标 + 操作类型 + 关键参数 + 授权约束摘要（由 proto 字段明确定义，防"关键参数"解释分歧）。

### 4.3 可信边界重申（总体方案 §4.2 的工程化表述）

- ICS、GW、TCS、预算/业务操作账本、密钥与持久存储属于**本域可信计算基（TCB）**。
- **模型与运行时不属于权限判定 TCB**：RUN 产生的一切"我要调用 T / 委托 B / 发送 X"均为**提议**，生效前必须经确定性校验（06 §2、03 §4.6）。
- 运行时不得绕过 GW 直接持凭证出域：网络层默认拒绝直连出域，凭证仅存于 GW 凭证库（08 §3.4）。
- 凭证、完整提示词不得进入普通消息正文与日志（10 §4）。

### 4.4 错误码命名空间

错误码统一为 `ANET-<区域>-<名称>`，区域：`CMD`（命令）、`TSK`（任务）、`EFF`（业务操作）、`BUD`（预算）、`AUT`（授权）、`DSC`（披露）、`PRT`（协议/适配）、`DIR`（目录）、`NET`（网络）。完整清单见文档 03 §7 与 04 §9；新增错误码必须同时登记到 13 的测试追踪表。

## 5. 保证边界（详细设计的前提）

沿用总体方案 §4.3 三层保证，并落实为可检验语句：

| 层次 | 本设计的可检验形态 |
|---|---|
| 本域控制保证 | 不变量 I1–I10（文档 13 §1）在故障注入下成立 |
| 跨域协议保证 | 08 §4/§5 的映射核对表 + 协商扩展 `x-anet-reliable-admission` 的对端支持声明 |
| 业务结果保证 | `acceptance_policy` 指定的验证器输出 `VERIFIED` 回执；验证器能力之外的结论不背书 |
