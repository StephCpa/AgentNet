# 27 · 权威父链校验

状态：2026-10-27，委托实现的前置增量；CreateSubtask 和完整 M1/M2 尚未完成。

## 从根授权到逐层校验

原 ICS、TCS、执行器各自限制 `parent_grant_id IS NULL`。本轮将决定签发、T2/local-tx 接纳和最后出站守卫接入同一个权威父链校验器；不通过放宽 SQL 的根节点条件来直接接受子授权。

校验器发现最多 64 个节点的无环路径，按 grant_id 字典序取得共享锁，锁后重读并核对父指针，再锁根同意。每一层必须有效、未撤销，根标识、任务父子边、域、主体与同意版本一致。子权限的动作、资源、数据类、空间域、委托范围与时间窗只能收缩，剩余深度必须递减；根授权仍受实际用户同意的主体、actor、策略和时间窗限制。父指针在锁等待中改变会被拒绝。

随后等待账户或执行作业锁时，仍保留父链与同意锁；接纳/发送前用新的数据库时刻复核有效期。执行器在链锁之后复核 actor/目标绑定，避免使用锁前读取的身份与权限条件。已接纳 effect 的原事实仍可恢复，祖先撤销只阻止新授权、新接纳和新发送，不覆盖已有业务结果。

根授权摘要保留旧格式；子授权使用 `anet.grant-chain/1`，将所有祖先快照和父/根关系纳入摘要，不能只对叶节点做摘要。决定有效期不超过整条链的有效期。

## 收缩原语与边界

`Attenuate(parent, proposal, recipient)` 先拒绝扩大父权限的提案，再求与接收方策略的交集；不会先裁剪越权提案再当作合法请求。它使用可信事务输入，是后续创建路径的内部原语，尚未作为可据此签发权限的外部 API。

当前资源/动作按精确词条比较，不做通配符或跨域语义推导；时间窗取 `grants.not_before/expires_at` 权威列。存储中的未知 rights 字段被拒绝，不能悄悄忽略额外约束。公共根授权签发仍限定 depth=0，同一域的任务访问仍要求 caller principal 是任务 owner。

测试通过预置三层权威记录验证链判定、T2 和 mock 目标发送；没有将此称为完整 CreateSubtask。接收方策略的持久绑定、契约委托限制、跨 owner 的 subject/actor 分离、父账户 H→D 与子账户创建、子任务取消传播和 token exchange 继续实现。无同意的旧库级 fixture 只允许单个不可委托根，网络接口不会签发这种根。

## 验证
