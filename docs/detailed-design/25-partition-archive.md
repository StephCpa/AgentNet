# 25 · 可恢复分区归档与过期清理

状态：2026-10-27，M1 增量；完整里程碑退出条件不变。

## 从分区维护到持久归档

迁移 012 新增归档作业、Parquet 分片检查点和按域/任务检索的索引。`archived` 维护同一数据库内跨域共用的事件/审计月分区，正常周期为每日一次。事件分区上界满 180 天、审计分区上界满 365 天后才可摘除；不是看到其中某条旧记录就删除整月。

事务内冻结写入/截断、摘除分区并登记 DETACHED；随后分片导出到 S3，远端回读校验后才保存游标。清单完成后进入 EXPORTED，再次验证所有远端分片、清单和源行数，最后同事务 DROP 源表并登记 COMPLETE。会话级维护锁在进程终止时由数据库释放；网络等待不持有热表锁。

每个 Parquet 记录保存来源表、微秒时间、序号、域、任务及完整原行 JSON。按任务的索引指向分片；对象 key 含摘要，条件写入禁止覆盖，版本化桶记录并使用已验证的 VersionId。读取会校验内容，不能把 ETag 当作数据摘要。存储位置变更不会被自动接受为旧作业的恢复目标。

## 恢复与可见性

| 中断位置 | 保留事实 | 恢复 |
|---|---|---|
| 摘除事务之前 | 原分区仍挂接 | 重新筛选并锁定 |
| DETACHED 后 | 冻结源表、作业记录 | 继续导出；查询仍读源表 |
| 对象已上传、游标未提交 | 原源表、可能多出的对象 | 原游标重新导出并验证，不覆盖既有对象 |
| EXPORTED 后 | 源表、分片与清单 | 重新验证远端后再删除源表 |
| DROP 后目录写入失败 | 整个事务回滚 | 源表恢复，作业继续 EXPORTED |
| COMPLETE 后进程终止 | 目录、索引和对象版本 | 直接恢复冷热查询，不再创建源表 |

查询接口同时读取热表、摘除源表及已完成归档；锁顺序避免切换期间漏读或重复。它目前是运维库接口/CLI，未接入通用 worker 事件重放 RPC。业务权威表不被此作业删除，TCS 当前接纳与对账路径不依赖被摘除的事件分区。

实测前已修正一处时区缺陷：Windows 的 pgx 返回本地时区时间，原“零点月边界”判定误拒绝 UTC 分区；边界和清单游标现在统一为 UTC，导出及冷热查询也固定 SQL 会话时区。该约束还保证跨机器恢复时清单内容不因本地时区变化而变化。

回归还检出时区读取事务提交位置错误：正常批次的检查点被外层事务回滚，重复上传直到超时。现于关闭结果集后提交读取事务，再独立执行对象 I/O 和检查点事务；新增字节上限分片用例，与常规行数分片、空分区及超大行用例共同覆盖该边界。此前失败运行未计入通过证据。

## 清理与证据边界

command_inbox 仅在 expires_at、可信 not_after 都过去，且接收时间超过七天后清理；12 的“≤168h”改为“至少 168h 且不早于 not_after”，与 02/04 一致。清理以每表最多 1,000 行的小事务循环排空当前可处理积压，并先于归档执行，避免对象故障拖住清理。DONE outbox 仅按 dispatched_at 保留 168 小时，避免夏令时缩短保留期；有 dead-letter 引用的行保留。投递 inbox、网关原命令绑定、effects/receipts、业务表和 artifacts 不删除。FI-13 使用真实清理函数，再用原签名命令重放验证不会重新建任务。

当前不执行对象存储的合规到期删除；域的冷存保留、桶访问策略、对象耐久性与数据库目录备份仍需部署配置。配置和迁移回退见 [archive README](../../services/archive/README.md)。归档不替代 WAL/PITR 或备份恢复演练，也不构成完整 M1/M4 退出。

最终独立集群门禁通过：**36 项 runner 检查、123 项数据库集成测试、8 项单测**；排除四个进程 helper 和嵌套子例。数据库测试分布为 TCS 33、delivery 8、execution 17、RPC 39、identity 15、archive 10，另加独立构建标签的真实 MinIO 1 项。`go vet ./...`、MinIO 标签的 vet 及 11 个生成绑定漂移检查均通过；PostgreSQL 已正常停止。

真实 MinIO 由固定官方源码 `RELEASE.2025-09-07T16-13-09Z` 构建，测试验证错误签名被拒、条件写入不覆盖、对象版本持久化、更新当前版本后仍读取原已验证版本，以及进程终止/重启后恢复。它与 HTTP 故障夹具分别计数，不将后者称为真实对象存储互操作。运行平台为 Windows amd64、Go 1.25.1、PostgreSQL 16.15；完整命令、模块来源、失败修复记录和原始日志见 [归档证据](../../test/evidence/2026-10-27/archive/README.md)。
