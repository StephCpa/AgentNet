# 22 · 网关入站签名与请求失败审计

状态：2026-10-27，M1 单域 SDK 入口增量；完整 M0–M4 目标不变。

## 已实现链路

`Gateway.SubmitCommand(intent_json)` → 实例 mTLS 认证 → 持久意图绑定/签名 → ICS 根许可 → TCS T1 → 原始接纳回执。

客户端只提供 `anet.intent/1` 意图，正文不能覆盖调用者、域、可信时效或签名。网关复用现有 mTLS 实例注册认证，持有独立 Ed25519 签名密钥；ICS 仍使用独立密钥核验用户同意和预算上限。新接口位于 `proto/anet/gw/v1`，实现位于 `services/gateway`，由 `anetd` 显式配置启用。

复核同时发现：原先事务只复核指纹/撤销，证书在锁等待中自然到期仍可能通过。本轮把已验证证书的 `NotAfter` 作为仅传输层可设置的上下文，GW/ICS/TCS 在锁后用数据库时钟再验有效期；签名 JSON 仍只绑定稳定身份。新增三个真实锁等待用例分别验证网关签名、ICS 许可和 TCS effect 接纳均拒绝到期凭证。

这是 14 §3 M1 所需四级最小流水线的单域 SDK 实现。08 的 agentgateway 挂接、跨域 OAuth/DPoP、披露检查、入口配额及 A2A/MCP 映射尚待后续工作，不能将本接口当作这些外部协议已经实现。

## 可信时效与断点恢复

首次请求在 `gateway_commands` 中按 `(domain, command_id)` 独占绑定认证身份和 JCS 意图摘要，同事务保存首次签名、`not_after` 与 `gw.command_bound` 审计。时效由服务选择，默认 5 分钟；重试、服务重启和 TCS inbox 清理均不得重新签发更晚期限。记录目前永久保留，未来归档须保留绑定和时效墓碑。

| 停止位置 | 已有事实 | 恢复 |
|---|---|---|
| 意图绑定前 | 无签名绑定 | 首次请求正常执行 |
| 签名落库后、ICS 许可前 | 原签名及原期限 | 复用签名，经 ICS 授权 |
| 许可落库后、T1 前 | 签名许可，无接纳事实 | 原许可尝试 T1；过期/陈旧则重新授权，不延长命令期限 |
| T1 提交后、回执读取/传输失败 | 任务、grant、账本、回执、inbox/outbox 已提交 | 同意图复用原签名/许可，TCS 返回原回执 |
| 原期限后 | 命令已过期 | 无条件拒绝，不能因 inbox 清理重新创建 |

网关签名绑定和许可都不等同于 ACCEPTED。已接纳的合法重试沿用 TCS 的回执恢复语义，不因用户随后撤销同意而制造第二份 grant；新接纳仍需当前授权。当前凭证失效仍阻断请求。

`gw.command_bound` 记录签名绑定，`tcs.command_accepted` 记录实际接纳，后者与任务/grant/账本/回执/outbox 在 T1 内原子提交。接纳审计写失败会回滚整笔 T1；前段持久签名及许可仍可供同命令恢复。

## 拒绝与未知的区分

注册 RPC 到达认证/handler 拦截器后的失败追加 `rpc.request` 审计，保存方法、稳定错误码和摘要。认证失败不使用正文或部分查库结果冒充已认证主体。策略/格式拒绝记 `deny`，取消、超时、内部故障或不可用记 `unknown`；不落原始正文、密钥、令牌或数据库错误文本。

本轮还修复 T1 已提交后读取回执失败的返回语义：即使后续读取因为凭证撤销被拒绝，外层也返回 `Unavailable` 并记录 `unknown`，避免把已创建任务错误描述成未接纳。失败审计独立于已回滚的业务事务，并使用不随客户端取消的 2 秒有界上下文；写审计失败同样返回不可用。

TLS 握手失败、未知方法、拦截器之前的 protobuf 解码失败、进程在审计前死亡不在该审计覆盖内。网络入口观测与持续流身份复核仍须补齐。

## 验证

真实 PG16 与 mTLS 用例覆盖签名身份/域绑定、正文伪造、同 ID 改参、跨实例冲突、预算超限、并发首提、清理后过期重放、同意撤销后原回执恢复、许可落库后请求取消及陈旧许可重新授权、审计写失败回滚/不可用、匿名认证拒绝与角色拒绝。另以数据库故障注入覆盖已提交但回执无法读取的语义。

独立 `anetd` 可执行程序加载 GW 私钥，完成无客户端签名的接纳；终止并重启后再次提交相同意图返回原任务。此用例证明已完成接纳后的进程重启恢复，不替代所有签名/许可中间相位的 OS Kill 测试。

最终通过 **32 项 runner 检查、92 项数据库集成测试、6 项单测**；`go vet ./...` 和 9 个生成绑定文件漂移检查通过。计数排除 3 个子进程辅助入口。证据见 [`test/evidence/2026-10-27/gateway`](../../test/evidence/2026-10-27/gateway/)。开发首轮修正了流式 RPC 测试在 `Recv` 前判断成功的问题，最终运行无失败断言重试。
