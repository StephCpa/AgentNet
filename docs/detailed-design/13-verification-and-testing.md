# 13 · 验证与测试设计：不变量、故障注入与基准

状态：v0.2.2 复审修订（2026-10-27） ｜ 上游：总体方案 §14 ｜ 本文件是 M0–M4 各里程碑退出条件的规范来源。

## 1. 不变量 I1–I11：机制与测试映射

| 不变量 | 机制（设计落点） | 主要验证 |
|---|---|---|
| I1 接纳回执只能在持久提交后返回 | T1 提交序（03 §6.1）；`receipts.issuer` 必填 | TLA+ Inv1；FI-01 |
| I2 只有当前 epoch **且为有效租约持有者**可接纳新操作 | T2 守卫（epoch + lease holder 实例绑定）+ 出域 epoch 校验（04 §5） | TLA+ 动作性质；FI-04（含旧 worker 伪装新 epoch 变体） |
| I3 同一操作标识不能绑定不同参数 | 去重摘要比对；冲突=拒绝响应不改写原绑定（03 §6.1/§6.2、04 §4.2） | TLA+ BindingImmutable；FI-07 |
| I4 已终结任务不能被旧消息重启 | 终态守卫触发器 + 状态机（02 §3.1、03 §5） | TLA+ TerminalStable；FI-08 |
| I5 S+H+D ≤ B（v0.2） | 行锁 Reserve + 双表延迟约束触发器（05 §3、02 §3.4） | TLA+ BudgetLedger（双域）；FI-06、FI-12 |
| I5b 预留独占绑定（v0.2 新增） | 单行单目标 CHECK + 绑定不可改写触发器（05 §2/§4） | PG16 SQL 探针已通过；TLA+ 尚未建模 reservation_id |
| I6 子授权不能扩大有效权限（沿真实父链） | checkShrink（06 §3） | TLA+ AuthzShrink 步性质；FI-11 |
| I7 UNKNOWN 不得被伪装成失败后自动重做，**也不得被任何请求覆盖** | UNKNOWN 持久 + 禁自动重试 + 冲突不改状态（04 §4.2/§4.3、§6.3） | TLA+ UnknownPreserved/CommittedPreserved；FI-03 |
| I8 完成状态满足验收条件（VERIFIED 四元组绑定） | SUCCEEDED 守卫需 VERIFIED（03 §5、09 §7） | BM 主断言；验收器单测 |
| I9 取消后不再接纳新操作、既有操作继续对账 | T3 + T2 守卫 + 对账不中断（03 §6.3、04 §7） | TLA+；FI-05 |
| I10 安全约束不得在协议适配中静默丢失 | 适配映射核对表 + 出站再校验（08 §6、09 §8） | PRT 套件；FI-10 |
| I11 命令时效（v0.2 新增） | not_after 无条件检查 + inbox 保留 ≥ not_after（03 §6.1） | SQL 探针；FI-13 |

## 2. TLA+ / 状态模型（M0 交付）

**2026-10-27 v0.2.2 四个有界模型通过**（工具链、逐项结果、变异记录见 `test/tla/README.md`）：

| 模块 | 通过项 | 规模 |
|---|---|---|
| TaskMachine | Inv + 6 条**独立动作性质**（UnknownPreserved 等，`[][~(坏条件)]_Vars` 形式） | 383,593 states |
| CmdExpiry（新增） | I11：清理后重放不建第二个任务 | 10 states |
| BudgetLedger（重建为**双域模型**） | I5 + InvLedger（父账 D = 子域权利+在途守恒） | 8,008 states |
| AuthzShrink（重建为**真实父链**） | ChainMonotone（沿链单调收缩） | 33 states |

**守卫变异测试（12 项）**：12/12 被指定性质检出。新增接纳快照和 EpochFence 后，M3 被检出；旧版“预期冗余”结论撤回。M2b/M3b 分别验证旧 worker 伪装当前代次、当前 holder 使用旧提案；M9/M10 覆盖清理和去重守卫。解析/运行错误不计为检出。

界：Workers={w1,w2}, Cmds={c1,c2}, Effects={e1,e2,e3}, BudgetMax=2（使预算与重做变异互不掩蔽）。

- LLM 抽象为**能提出任意行动的非确定性组件**（含"重试换参数""伪装代次"——Admit 的 `ce` 参数即可查询的提案代次）。
- Crash 相位覆盖（04 §9 四窗口）仍为 TODO（v0.3 计划）；子任务树展开待 BudgetLedger 扩展。
- AgentRFC 的协议组合检查方法作参考。

## 3. 故障注入测试矩阵（FI）

统一在 devnet（12 §2）执行；所有危险操作使用模拟业务系统或隔离环境。注入工具：崩溃钩子（按 04 §9 的 phase）、响应丢弃器、消息复制/乱序器、域间分区黑洞、时钟偏移、恶意对端仿真（伪造能力声明/回执/重放旧消息）。

| # | 场景（总体方案 §14.2 同序） | 注入手段 | 期望行为 | 不变量 |
|---|---|---|---|---|
| FI-01 | 任务提交后、ACK 返回前崩溃 | T1 COMMIT 后、回包前 kill TCS | 客户端重试按 `command_id` 查回同一 task 与同一 ACCEPTED 回执；无第二个任务 | I1 |
| FI-02 | 远端已创建任务、句柄丢失 | 丢弃对端 ACCEPTED 响应 | 按 by_command 查询恢复 `peer_task_ref`；不重复创建 | I1 |
| FI-03 | 外部操作完成后本地崩溃 | mock 业务系统已执行、ADP 记录前崩溃 | 幂等键/查询对账 → COMMITTED；`opaque` 类转 UNKNOWN 并升级，**不自动重发** | I7 |
| FI-04 | 旧 worker 接管后复活 | 租约过期触发接管后唤醒旧 worker | 旧 epoch 被拒 `ANET-EFF-FENCED`；旧 worker 查询并伪装当前 epoch 仍被 holder 校验拒绝；出域请求由 GW fencing 拦截 | I2 |
| FI-05 | 取消与提交并发 | 并发调用 Cancel 与 AdmitEffect | 行锁串行化；两种顺序都有明确解释（取消先 ⇒ 接纳拒绝；接纳先 ⇒ 操作继续对账） | I9 |
| FI-06 | 多子任务并发申请超额预算 | 并发 Reserve 冲击根账户 | 合计不超 B；超额者收 `ANET-BUD-EXHAUSTED` | I5 |
| FI-07 | 重试时参数改变 | 恶意 SDK 同 effect_id 换参数 | `ANET-EFF-PARAMS-CONFLICT` 拒绝响应 + conflict 行留档；**原 effect 状态/绑定/预算/对账资格不变**（v0.2） | I3/I7 |
| FI-08 | 消息过期后重放 | 超过 dedup_retention 后重发旧命令 | `ANET-CMD-EXPIRED` + 恢复流程；旧消息不能复活终态任务 | I4 |
| FI-13 | 去重记录清理后重放（v0.2 新增，评审 §6.1） | 时效过后按清理规则删除 inbox 行 + 重放命令 | `not_after` 检查拒绝；**不得创建第二个任务** | I11 |
| FI-09 | 证据引用失效/摘要遗漏限制 | 篡改产物或删引用 | 补取或验收失败"证据不足"，不得残缺通过 | I8 |
| FI-10 | 协议桥丢失授权约束 | 适配器缺陷注入（剥离扩展字段） | 出站再校验失败，接纳前拦截 | I10 |
| FI-11 | 恶意内容自称管理员授权 | 伪造正文身份字段 | 权限不变（身份只认可信接入层绑定） | I6 |
| FI-12 | 子域断网、根域回收额度 | 分区 + 根域 Release 尝试 | 未确认释放的 tranche 不被重复分配；恢复后按上报结算 | I5 |

## 4. 协议映射回归（PRT）

- 用例组：A2A 状态映射全迁移对（08 §4.2）、MCP 断流语义（SSE 关闭=取消）、Tasks 句柄恢复、取消跨域确认、扩展协商失败降级。
- 触发时机：每次适配器版本升级、对端协议版本变化（08 §6）；PRT 不过不上线。
- 恶意对端仿真：能力谎报（声明 reliable_admission 但不去重）→ 探测测试识别并标记目录 `quality_alert`。

## 5. 基准实验（BM，staging）

- **任务集**：总体方案 §三场景的可执行实例化（研究分析 / 检索委托 / 计算提交 / 审核验收，≥3 类 × ≥20 任务/类）；冻结模型、工具、任务集合与预算。
- **配对比较**：同一任务在四组基线上运行——
  - B1 直接互联（A2A/MCP + 框架默认状态管理）；
  - B2 成熟工程组合（持久工作流 + OAuth + 事务预算 + outbox + 幂等适配）；
  - B3 现有 Agent 网络栈（适用组件：AGNTCY / agentgateway / AgentMesh 组合，M0 选定）；
  - B4 本设计（同 B2 底座 + 跨协议约束 + 证据恢复 + 受控动态路由）。
- **指标**（13 §5 全成本口径，10 §5）：任务效果（独立验收成功率、错误操作率、证据完整性）；正确性（重复业务操作数、越权数、预算超支量）；恢复（UNKNOWN 比例、对账时长、故障恢复时长）；成本（全流程 token/费用/消息量/控制开销/端到端时延）。**必须同时报告误拒绝率**。
- **消融**：通信参与者上限 d（07 §6）、L1/L2/L3 表示策略（09 §8）、恢复能力门控（07 §4）分别关闭对比。
- 统计：任务配对 bootstrap 置信区间；B4 相对 B2/B3 的增益须"可解释"（能归因到具体机制）方计为成立——否则按总体方案 §14.3 调整研究主张。
- **诚实性条款**：模拟大规模逻辑 Agent 的实验单列，不与真实复杂 Agent 协作能力混报。
