# 29 · 本域子树取消与预算结清

状态：2026-10-27，第 29 阶段快照；本域结清与取消传播已实现验证，后续子任务 GW 入口见 [30](30-gateway-subtask-ingress.md)。完整 M0/M1/M2 仍未退出。

## 结清的权威依据

`TaskControl.CloseSubtaskBudget` 只接受 `child_task_id`，不接受调用方自报用量或归还额。任务 owner、接收 Agent 或直接创建 Agent 可以请求结清，仍须通过当前 mTLS 身份与数据库实例状态检查。业务执行授权与结清管理权限分别检查。

首次结清须满足：子任务为 CANCELLED/FAILED/SUCCEEDED，未冻结；没有 ADMITTED/UNKNOWN effect，没有任何 HELD 预留或委托余额；所有直接子任务都已结清，包括零预算子任务。每个非零维度的原分配记录必须与父子账户、金额、创建命令及 RELEASED/delegated 预留一致。根任务不适用该 API。

逐维以权威账本的旧子额度 B 和已结算 S 执行：

| 对象 | 原子变化 |
|---|---|
| 父账户 | D 减 B；S 加子 S；可用余额增加 B−子 S |
| 子账户 | B 改为 S、D 保持 0，设置 closed_at，永久封账 |
| 委托记录 | 保存首次 closed_at 和四维 allocated/settled/returned 结果 |
| 事实记录 | 父子事件、审计及 CHILD_BUDGET_SETTLED outbox 同事务提交 |

迁移 014 使已封账账户、原委托绑定及首次结清结果不可改写。并发与重试读取同一结果并返回 `existing=true`；不会重复增减父账本。子账户保留历史 S，因此树级费用汇总不能再把已汇入父 S 的子 S 重复相加。仍活跃的父任务可重新使用归还额度，已取消的父任务不能因此恢复执行。

子任务取消只停止新的接纳，UNKNOWN 责任继续保留。受信适配器的迟到终态事实先完成原 effect 结算，再允许子账本结清；已结清后的相同事实重放返回原结果。超支冻结、未绑定 HELD 或在途 effect 都返回 `ANET-BUD-SUBTASK-NOT-READY`，不猜测剩余责任。

## 持久取消传播

T3 提交 CANCELLED 后，现有 outbox 投递到本域 inbox。接收器核对权威任务已取消，将实际本域直接子任务写入 `task_cancellations`，与 inbox 接纳同事务提交。`cmd/outboxd` 同时运行投递和 `services/tasktree` 工作器；只启动 anetd 不会完成这段异步传播。

树工作器每次锁定一个工作项和目标任务，验证父边以及通向已取消源的同域、无环、有界祖先链。消息正文和队列行都不是取消凭据。非法工作项标为 INVALID，后续真实取消可替换；来自已取消兄弟任务的伪造源也被拒绝。外域引用不进入本地传播队列。

非终态目标迁移为 CANCELLED，版本递增一次，事件、outbox、审计、后代入队和工作项 DONE 原子提交。已完成/失败的中间节点保持原终态，仍向其后代传播。取消不修改 effect 或预算。任一循环失败时 outboxd 退出交由监督器恢复；待处理工作存于数据库。

## 锁序与故障边界

结清先按 task_id 排序锁父子任务，再锁委托记录和按 account_id 排序的父子账户；所有写入后复查调用身份。传播只锁工作项和一个目标任务，入队后代不获取后代 task 行锁。队列任务引用故意不设 task 外键，工作器用权威祖先检查代替，避免父节点事务入队时与子节点结清形成反向锁序。

创建子任务和取消目标竞争同一任务行锁：创建先提交，则取消事务能看见并入队新子任务；取消先提交，创建守卫拒绝。事务内没有外部调用。提交前被 OS 终止时全部回滚，提交后、返回前被终止时由持久结果恢复。

## 验证与剩余工作

新增九项顶层数据库测试，覆盖 UNKNOWN 迟到结算、未绑定预留、冻结/活跃任务、零额度及嵌套汇总、回滚与并发结清、锁等待期间身份撤销、伪造源/兄弟分支访问、重放、真实 outboxd、创建/取消竞争。结清与传播各验证提交前和提交后两个 OS 终止窗口。

开发运行检出工作器使用不存在的 outbox 唯一约束：已移除错误的 ON CONFLICT 目标，依赖锁内终态转换保证取消事件只写一次。两个嵌套测试将纳秒签名期限精确复制到微秒持久化父期限边界，触发正确的收缩拒绝；测试改用严格位于父时间窗内的期限。保留失败日志与修正后的定向结果，不将失败运行计为通过。

本轮没有扩展 TLA+ 的崩溃相位/任务树模型，进程测试不替代形式证明。完整契约与 VERIFIED 验收、UpdateTaskStatus、GW/SDK 子任务入口、接收方策略管理、跨域取消/结清、token exchange、真实 A2A/MCP 对端及完整 FI/BM 仍待完成。终态中间节点测试使用可信 fixture 写入状态，未宣称公共状态迁移 API 已实现。

全量运行曾因既有 TestIdentityDaemonProcess 的临时 instancekey.exe 清理占用失败；没有业务断言失败。已退出进程后 DELETE-access 探针先返回错误 32，稍后恢复可访问。测试现仅对 Windows 错误 32 有界重试该已退出可执行文件的删除，最多 5 秒；不重试命令或断言，其他错误或持续占用仍报失败。失败日志及两次访问探针保留在本轮证据中。
