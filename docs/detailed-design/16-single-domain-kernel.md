# 16 · 单域事务内核与 JCS 验证

状态：2026-10-27，M1 首个实现切片完成；M0/M1 均未整体退出。前序复审记录见 15。

## 1. 本轮交付

| 工件 | 内容 |
|---|---|
| `services/tcs` | Go + pgx 的真实 PostgreSQL 事务：T1、T2、T3、查询、预留/未绑定释放、租约领取/续期/接管、结果对账与结算 |

没有在库事务内执行网络调用。T1/T2/T3 的外发意图与权威状态原子写入 outbox，投递器尚待实现。

## 2. 本轮保证及实测

- T1 并发同命令只建立一个 task/ACCEPTED 回执/outbox；重新建立连接池后重试仍取回同一事实。数据库故障使全部临时写入回滚。
- GW 的签名覆盖 caller、not_after、契约和限额；不能只验证调用身份后相信请求自填时效。锁等待后重新读取时刻，避免 PostgreSQL now() 固定在事务开始带来的过期接纳。
- T2 验证 ICS 的 Ed25519 签名、完整绑定字段与数据库中的有效根授权；授权、目标操作和必需维度不能由客户端声称替代。核对已发生事实优先于首次接纳的版本/租约守卫。
- 接管保留旧执行者语义：旧 epoch 被拒；旧 worker 即使使用新 epoch 与新 lease_id 仍因 holder 不符被拒；当前 holder 的旧提案也被拒。宽限期内禁止接管。
- 四维预留全成或全败；一笔已绑定预留不能支持另一个 effect。Reserve 并发不会重复分配同一预算。
- UNKNOWN 保持 HELD；冲突不能覆盖原业务事实。取消后允许可信晚到证据结算，但不再接纳新 effect。相同结果不会重复记账。
- 不可信自报成本 0 按预留全额结算；超额报告保留原数值和证据、保持占用并冻结新支出，不把实际成本截断成预算内数字。
- 时效、租约和实例撤销都覆盖了真实数据库锁等待后的复核路径。

实测：**22 项顶层 Go 数据库集成测试 + 10 个授权决定绑定子例通过**；2 项 Go JCS 单测通过；既有 SQL 探针及 003 迁移通过；`go vet ./...` 通过；JCS 三方各 **20/20** 通过。

证据保存在 [`test/evidence/2026-10-27/kernel`](../../test/evidence/2026-10-27/kernel/)。数据库是 PostgreSQL 16.15（含 pgcrypto）；Go 1.25.1、Node 22.20.0、Python 3.10。本轮未更改 TLA 模型，其结果仍以 15 的 v0.2.2 快照为准。

## 3. 实现范围

当前实现是**库级事务内核**，不是已上线的 TCS 网络服务。Caller 必须来自可信认证层，命令/决定/结果的公钥必须由部署配置提供。测试显式创建本域主体、实例和根授权；T1 不擅自授予工具执行权限。

支持本域根任务与根授权；尚未实现委托授权父链、子任务树、tranche/attempt 账务、VERIFIED 驱动的成功迁移、租户外的所有权策略。已有 gRPC protobuf 还未与该内核的签名封装完成绑定。细节和运行方式见 [`services/tcs/README.md`](../../services/tcs/README.md)。

当前故障测试为数据库事务失败、丢弃返回结果后重建连接池和并发锁等待，不冒充进程 kill、网络丢包、真实外部副作用或完整 FI 套件。
