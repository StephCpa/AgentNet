# 26 · 单域控制路径微基准

状态：2026-10-27，M1 首份微基准；完整 M1/M3/M4 退出条件不变。

## 测量对象

新增 `microbench` 构建标签的 RPC 驱动，使用生产 GW/ICS/TCS 和 local-tx 实现，经真实 TCP/mTLS 访问独立 PostgreSQL 16。测量四条路径：GW 新命令、原回执重放、共享账户预留、GW 到 local-tx 完整链。完整链包含 GW、租约、决定、四维预留和本地执行共八次 RPC。

每条路径分别使用 1/8 并发，每个配置重复三次，每次先按同等并发预热 20 次，再测量 200 次。每次重复建立新域和任务，顺序轮转；同一个数据库保留前序测试和采样产生的数据，报告记录测量前 tasks 数。输入构造、重放预建及首次 TLS 建连不计入测量；动态后续请求构造、响应检查和统计开销计入完整操作时延。

驱动保存每次请求的耗时、阶段耗时、RPC 调用数、未压缩 protobuf 字节和错误。测量后核对任务数量、原回执一致性、预留数及越界拒绝、本地业务/结果数量和结算维度。返回成功但数据库事实不符仍使门禁失败。报告程序从原始样本重算吞吐和 nearest-rank 分位，拒绝缺项、错误、重复配置或事实未核验的数据。

## 证据口径

这是闭环本地微基准。客户端与 gRPC 服务共用 Go 测试进程，PostgreSQL 独立进程；无开放到达速率、跨机器网络、用户登录、LLM 或外部业务流量。protobuf 字节不含传输协议、SQL 和审计流量。报告使用每次重复统计量的中位数及范围，不把短时重复混作独立任务样本；不能据此断言生产 200 msg/s、复杂 Agent 规模或 B4 对 B2/B3 的收益。

首轮小样本发现驱动把网关命令期限设为一小时，超出已有五分钟配置上限，初始化被拒；修复为服务默认值。另将预热从串行改为与测量相同并发，避免把连接池首次扩展混入正式样本。所有正式源码修改在最终独立集群运行前完成，失败运行不计入正式结果。

最终共 **4,800 次测量操作、13,200 次 RPC**，失败与误拒绝均为 0，全部数据库事实核对通过。环境为 Ryzen 9 5900HS（8 核/16 线程）、约 23.4 GiB 总物理内存、Windows amd64、Go 1.25.1、PG 16.15；fsync、synchronous_commit、full_page_writes 均启用，连接池上限 16。

| 路径 | 1 并发操作/s | 8 并发操作/s | 8 并发 p95 ms |
|---|---:|---:|---:|
| GW 新命令 | 62.0 | 353.9 | 26.265 |
| 原回执重放 | 165.5 | 917.4 | 10.424 |
| 共享账户预留 | 271.6 | 356.2 | 25.981 |
| GW 到 local-tx 全链 | 17.9 | 118.0 | 75.965 |

各列均为三次重复统计量的中位数。共享账户预留的吞吐增长较小且排队延迟增加，与当前 task/account 行锁串行化实现一致；这属于结合代码的解释，尚未用锁等待采样证明开销归因。完整链结果以八次 RPC 的总操作计量，不能与单次预留吞吐直接比较。当前结果用于建立后续变更的参照，未据此修改安全锁或宣布达到生产容量目标。

完整门禁 **38 项通过**：现有 123 项数据库集成测试、8 项 Go 单测保持通过，另有微基准运行及报告校验两个门禁；微基准的顶层测试和 24 个配置/重复子例不计入数据库测试数。报告验证器的 5 项 Python 测试、`go vet ./...`、microbench 标签 vet 和 11 个生成绑定漂移检查均通过，隔离 PG 已停止。逐轮范围、p50/p95/p99、方法和原始样本见 [正式报告](../../test/evidence/2026-10-27/microbench/microbench-report.md)；命令、环境和日志见 [证据说明](../../test/evidence/2026-10-27/microbench/README.md)。
